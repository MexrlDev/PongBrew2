# PONG 2 (PongBrew 2) for PS4

A complete Pong game for jailbroken PS4 consoles, built with the [OpenOrbis](https://github.com/OpenOrbis/OpenOrbis-PS4-Toolchain)
toolchain. Created by **MexrlDev**.

Custom menu and arena backgrounds, two songs with a menu-to-game crossfade, four game modes, power-ups, DualShock 4
rumble and light bar effects, settings, stats and a credits screen.

> Homebrew needs a console that already runs a jailbreak (for example GoldHEN). This project does not contain or
> explain any exploit. It is a normal app, installed from a PKG.

## Features

- **Modes:** VS CPU (four difficulty levels), 2 PLAYERS (two pads), SURVIVAL (lives, score, rising speed), PRACTICE (wall).
- **Power-ups:** wide paddle, shrink opponent, slow motion, multi-ball, freeze, extra life. Toggle in Settings.
- **Music:** menu song only in the menus. Starting a match fades it out and fades the game song in (loops). Back in the
  menu the game song fades out and the menu song returns. Pausing lowers the game song.
- **Sound effects:** synthesized at runtime.
- **DualShock 4:** light bar follows your player colour, flashes on scores and goes red when you lose a life. Rumble on
  hits, goals and power-ups. Both can be switched off in Settings.
- **Menus:** Play, Settings, Stats, Controls, Credits, Exit. Colour themes, volumes, points to win, screen shake.
- **Saved data:** settings and stats are written to `/data/pongbrew2.cfg`.

## Controls

| | Menu | Match |
|---|---|---|
| D-pad / left stick | Move | Move paddle |
| X | Select | Dash (L1 / L2 also dash) |
| O | Back | |
| OPTIONS | | Pause |

Player 2 uses the second connected pad (or the second logged-in user's pad).

## Performance (measured on a real console)

The OpenOrbis SDL port only has a software renderer, so the game draws every pixel itself with its own small rasterizer
(`src/gfx.c`).

| Build | PS4 Pro boost mode | Normal mode |
|---|---|---|
| default, native 1920x1080 canvas | 60 fps | 30 fps |
| `make SD=1`, 960x540 canvas doubled to 1080p | 60 fps | 60 fps |

If you want 60 fps on a base-mode console, build with `make clean && make SD=1`. Other canvas sizes have not been tested.

## Requirements

- Docker image `openorbisofficial/toolchain:latest` (OpenOrbis SDK v0.5.1), or a local install with `OO_PS4_TOOLCHAIN` set.
- Python 3 with Pillow and numpy (asset generator), and ffmpeg (re-encodes the songs).
- The Poppins Bold font for the generator: put `Poppins-Bold.ttf` in `tools/` (SIL OFL) or install it system-wide.
- Go (only to build `create-fself`, done by `tools/build-create-fself.sh`).

## Building

From a fresh clone, inside the toolchain container:

```sh
sh tools/build-create-fself.sh    # once: builds tools/create-fself
chmod +x tools/*
make assets                       # generates backgrounds, icons, font atlases, re-encodes the songs
make                              # check, compile, eboot.bin, param.sfo, PKG
```

Use `make clean` first whenever a header changed (the Makefile only tracks `.c` files). For the 960x540 canvas:

```sh
make clean && make SD=1
```

What the Makefile does:

1. Compiles `src/*.c` with `-DPS4_BUILD` for `x86_64-pc-freebsd12-elf` and links with the SDK and its bundled SDL2.
2. `tools/create-eboot-golden` wraps the real `create-fself` and fails the build unless `eboot.bin` starts with the
   SELF magic `4F 15 3D 1D`.
3. Copies the `sce_module/*.prx` stubs and `right.sprx` from the SDK, builds `param.sfo`
   (TITLE_ID `PONG00002`, CONTENT_ID `IV0000-PONG00002_00-PONGHOMEBREW0002`).
4. Packs `eboot.bin`, `sce_sys/`, `sce_module/` and `assets/` into the PKG with `PkgTool.Core`.

Install: copy the `.pkg` to a USB drive, delete any older install of the app, install with the GoldHEN Package Installer.

## Assets

- Songs: put MP3s at `assets_src/Menu_source.mp3` and `assets_src/Game_source.mp3`, then `make assets`. They are
  re-encoded to 48 kHz stereo. **Use music you have the rights to.**
- Credit image: `assets_src/credit_MexrlDev.jpg`.
- Backgrounds, icon and splash are generated by `tools/gen_assets.py`.

## Testing without a console

```sh
SDL2_PREFIX=/path/to/sdl2 sh test/run_tests.sh      # or: make test
```

Builds the game against `src/platform_pc.c` and runs a headless test: menu flow, every mode, pause, two pads, settings
saving, light bar and rumble calls, the song crossfade, a BGR888 present check and a per-screen timing report.
Screenshots of every screen are written to `test/out/`.

## Project layout

```
src/game.c          screens, matches, AI, power-ups, effects
src/gfx.c           software rasterizer, text, present path (BGR888 aware)
src/audio.c         mixer: synthesized effects, two MP3 songs with fades (minimp3)
src/platform_ps4.c  scePad (light bar, rumble), sceAudioOut thread, clean exit
src/platform_pc.c   keyboard / gamepad stand-in for the PC test
src/main.c          SDL setup, splash hide, fixed 60 Hz loop
tools/              build helpers and the asset generator
test/               headless PC test
```

## Notes for PS4 homebrew developers

- `sceSystemServiceHideSplashScreen()` right after the window exists, or the splash covers the game forever.
- Exit with `sceSystemServiceLoadExec("exit", NULL)` after joining your threads. Returning from `main` or tearing SDL
  down by hand ends in `CE-34878-0`.
- The PS4 SDL window surface is BGR888. A present path that only handles ARGB falls back to a very slow converter.
- Avoid SDL blended or scaled blits; they cost over 100 instructions per pixel on the console.
